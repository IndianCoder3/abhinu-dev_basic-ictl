# Contributing to Abhinu.Dev Basic ICTL

First off, **thank you** for considering contributing! 💛  
Whether it’s bug fixes, new features, examples, documentation, or helping polish the IDE, your contributions are welcome.

This guide will help you get started quickly and follow the conventions we use in this project.

---

## How to Contribute

### 1. Fork & Clone

1. Fork the repository: [https://github.com/IndianCoder3/abhinu-dev_basic-ictl](https://github.com/IndianCoder3/abhinu-dev_basic-ictl)  
2. Clone your fork:

```bash
git clone https://github.com/YOUR_USERNAME/abhinu-dev_basic-ictl.git
cd abhinu-dev_basic-ictl
```
---

### 2. Create a Branch

Always create a feature branch for your changes:

```bash
git checkout -b feature/your-feature-name
```

Examples:

* `feature/add-new-command`
* `feature/fix-typo`
* `feature/improve-examples`

---

### 3. Make Changes

* Code improvements go in `code/`
* Web IDE improvements too go to `code/`. If you have finalised to use a build, copy it over to `ICTL-StudioOnline_Release`
* Documentation goes in `README.md`, `HISTORY.md`, or new Markdown files
* Examples go in `code/examples/`

**Tips:**

* Follow the existing code style (indentation, naming)
* Include comments for clarity
* Test your changes locally before committing

---

### 4. Commit Your Changes

Write **clear, descriptive commit messages**:

```bash
git add .
git commit -m "Add Math.Sqrt command with example"
```

---

### 5. Push & Create Pull Request

Push your branch:

```bash
git push origin feature/your-feature-name
```

Then open a Pull Request on the main repo. Include:

* What your change does
* Any issues it fixes (if applicable)
* Screenshots if it’s a UI change (for website)

---

## Areas Where You Can Help

* **Core Language**: Add commands, fix bugs, improve parsing
* **IDE/Studio**: Improve the web editor, add features, polish UI, polish VS Code Extension
* **Examples**: More sample programs for learning purposes
* **Documentation**: Correct typos, update commands, write tutorials, and add comments to code for clarity
* **VS Code Extension**: Snippets, language support, or bug fixes

---

## Coding Guidelines

* Use **4 spaces** per indentation level (or use tab with indent-to-space set to 4)
* Keep variable names clear (`Variables.Counter`, not `X`)
* Include comments for tricky parts
* Keep functions and blocks small and readable
* Test your changes thoroughly

---

## Reporting Issues

If you find a bug or have a suggestion:

1. Check if the issue already exists
2. Open a new issue on GitHub with:

   * Clear description
   * Steps to reproduce
   * Screenshots if relevant

---
